## 파일 5개가 각각 하는 일

```
appsscript.json   설정표    시간대, 실행 방식, 웹앱 접근 권한  (편집기에서 기본으로 숨겨져 있음)
Code.gs           서버      스프레드시트를 읽고 쓰는 코드. 브라우저는 이 파일을 볼 수 없다
index.html        뼈대      사용자가 보는 화면의 구조
css.html          모양      색·글씨·간격  (앱스 스크립트에는 .css 파일을 만들 수 없어 .html로 만든다)
js.html           동작      버튼을 눌렀을 때 서버에 부탁하는 코드
```

```
[브라우저]  index.html + css.html + js.html
     │
     │  google.script.run.함수이름(값)      ← 부탁한다
     ▼
[구글 서버]  Code.gs
     │
     │  SpreadsheetApp                      ← 직접 만진다
     ▼
[스프레드시트]
```

## 처음 만드는 순서 (10분)

1. **구글 스프레드시트를 새로 만든다.** 이름을 붙인다. (예: `급식설문_데이터`)
2. 메뉴에서 **확장 프로그램 → Apps Script** 를 누른다. 편집기가 새 탭에서 열린다.
3. 편집기 왼쪽 **⚙ 프로젝트 설정** → `appsscript.json 매니페스트 파일을 편집기에서 보기` 를 체크한다.
4. 파일을 만든다. 왼쪽 **파일 + 버튼** 에서
   - `Code.gs` 는 이미 있다 → 내용을 전부 지우고 이 폴더의 `Code.gs` 를 붙여넣는다
   - **HTML** 로 `index`, `css`, `js` 세 개를 만든다 → 각각 붙여넣는다
     (파일 이름에 `.html` 은 쓰지 않는다. 앱스 스크립트가 자동으로 붙인다)
   - `appsscript.json` 도 내용을 붙여넣는다
5. **💾 저장** (Ctrl+S)
6. 함수 목록에서 **`setupSheet`** 를 고르고 **▶ 실행** 을 누른다.
   → 처음에는 권한 승인 창이 뜬다. `고급` → `안전하지 않은 페이지로 이동` → `허용`
   (내가 만든 스크립트가 내 시트를 만져도 되는지 묻는 절차다)
7. 스프레드시트 탭으로 돌아가 보면 시트와 머리글이 만들어져 있다.

## 웹앱으로 배포하기 (3분)

1. 오른쪽 위 **배포 → 새 배포**
2. 톱니바퀴 ⚙ → **웹 앱** 선택
3. 설정
   - 설명: `1차 배포` (아무 말이나 적어도 된다)
   - **다음 사용자로 실행**: `나`
   - **액세스 권한이 있는 사용자**: 아래 표 참고
4. **배포** → 나오는 **웹 앱 URL** 이 완성된 앱의 주소다. 휴대폰에서도 열린다.

| 액세스 권한 | 누가 쓸 수 있나 | 언제 고르나 |
|---|---|---|
| 나만 | 나 혼자 | 주제 ④ 개인용 |
| (학교 도메인) 내 사용자 | 같은 학교 계정으로 로그인한 사람 | **교내 설문·학급 관리에 가장 적절** |
| 모든 사용자 | 구글 로그인한 누구나 | 외부 응답이 필요할 때 |
| 모든 사용자(익명 포함) | 링크만 있으면 누구나 | 로그인 없이 받아야 할 때. 가장 조심해서 쓴다 |

> ⚠ **코드를 고친 뒤에는 다시 배포해야 반영된다.**
> `배포 → 배포 관리 → ✏ 편집 → 버전: 새 버전 → 배포`
> 매번 배포하기 번거로우면 개발 중에는 `배포 → 배포 테스트` 의 `/dev` 주소를 쓴다.
> (`/dev` 주소는 편집 권한이 있는 사람만 열 수 있다)

## 자주 나는 오류

| 증상 | 원인 | 해결 |
|---|---|---|
| `"응답" 시트가 없습니다` | setupSheet를 안 돌렸다 | 편집기에서 setupSheet 실행 |
| 화면에 `<?!= include('css') ?>` 가 글자로 보인다 | `createHtmlOutputFromFile` 을 썼다 | `createTemplateFromFile(...).evaluate()` 로 바꾼다 |
| 웹앱이 통째로 열리지 않고 템플릿 오류가 난다 | **index.html 주석 안에** 스크립틀릿을 적었다 | 앱스 스크립트는 주석 안까지 실행한다. 주석에서 지운다 |
| 화면 아래쪽에 코드가 글자로 쏟아지고 버튼이 죽는다 | js.html 안에 `</script>` 라는 **글자**를 썼다 (주석·문자열 포함) | 브라우저가 거기서 스크립트가 끝난 줄 안다. `<\/script>` 로 쓴다 |
| 버튼을 눌러도 아무 일이 없다 | 서버 함수 이름 오타 / 밑줄(_) 붙은 함수를 불렀다 | 이름을 맞추고, `_`가 붙은 함수는 화면에서 부르지 않는다 |
| `Script function not found: doGet` | 함수 이름이 `doGet` 이 아니다 | 대소문자까지 정확히 `doGet` |
| 저장은 되는데 화면이 안 바뀐다 | 결과를 `withSuccessHandler` 밖에서 썼다 | 화면을 고치는 코드를 핸들러 **안**으로 옮긴다 |
| 배포한 주소에서 이전 코드가 돈다 | 새 버전으로 배포하지 않았다 | 배포 관리 → 새 버전 |
| 날짜가 `Invalid argument` | Date 객체를 화면↔서버로 넘겼다 | `'2026-08-19'` 같은 문자열로 주고받는다 |

## 실행 기록 보기 (디버깅)

편집기 왼쪽 **▷ 실행** 메뉴에서 언제 무엇이 실행됐고 어떤 오류가 났는지 볼 수 있다.
`Logger.log('값: ' + x)` 를 코드에 넣어 두면 여기에 남는다. **추측하지 말고 찍어서 확인한다.**

## 데이터 윤리 (주제 ① 필수 · 나머지도 확인)

- 이름·학번은 받지 않는다. 없어도 답할 수 있는 질문이면 그 항목은 뺀다.
- 학년·반·성별을 다 받으면 이름이 없어도 사람이 특정된다(**재식별**). 조합 수를 줄인다.
- 응답 화면 맨 위에 여섯 가지를 밝힌다: 누가 · 왜 · 무엇을 · 어떻게 쓰이는지 · 언제 지우는지 · 거부 가능.
- 교내에서 설문을 돌리기 전에 **담당 선생님의 사전 승인**을 받는다.
- 발표 자료에 응답 시트 원자료를 그대로 붙이지 않는다. 통계와 그래프만 쓴다.
- 프로젝트가 끝나면 약속한 시점에 실제로 지운다. **삭제도 산출물이다.**
